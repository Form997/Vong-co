# V3.5 — HƯỚNG DẪN TRIỂN KHAI NHIỀU NHÁNH LÊN WEB

**Ngày ghi tài liệu:** 31/10/2026.  
**Nhánh cập nhật:** `v3.5-development`.  
**Phạm vi:** hướng dẫn vận hành, KHÔNG chỉnh sửa V1 đóng băng, V2 kiểm nguồn, ký âm, lời ca hoặc dữ liệu bài bản.

> **Điểm quan trọng:** website tra cứu 20 bản Tổ là **web tĩnh** được xây dựng thành HTML/CSS/JavaScript/JSON rồi công bố bằng **GitHub Pages** tại https://form997.github.io/Vong-co/. Đừng sao chép hướng dẫn Flask/Render để nhập `HOST`, `PORT`, `DATABASE_URL` hay `API_KEY` vào GitHub Pages. GitHub Pages không chạy máy chủ Python khi khách mở trang.

## 1. Từ mã nguồn đến web công khai

```text
feature/...  -->  v3.5-development  -->  Pull Request  -->  main
                     |                                    |
                 build/kiểm thử                       GitHub Pages
                     |                                    |
              Xem thử nội bộ                         Web công khai
```

- `v1-frozen`: **không sửa**.
- `v2-development`: hồ sơ kiểm nguồn, giữ chứng cứ và biên bản.
- `v3.5-development`: làm tính năng, sửa giao diện, kiểm tra trước phát hành.
- `main`: chỉ cập nhật khi Pull Request được xem và kiểm thử đạt.
- `feature/*`: từng thay đổi riêng, không tự đồng nghĩa với website đã được phát hành.

**Không hợp nhất hàng loạt nhánh vào production.** Mỗi nhánh có thể chứa cấu trúc, phiên bản dữ liệu hoặc chính sách khác nhau.

## 2. Các bước triển khai trên GitHub (từng nút bấm)

1. Mở https://github.com/Form997/Vong-co → tab **Code**.
2. Chọn nhánh `v3.5-development`, không chọn nhánh `v1-frozen`.
3. Sửa mã hoặc tạo nhánh `feature/ten-chuc-nang` từ `v3.5-development`.
4. Tạo **Pull requests → New pull request** với **base** là `v3.5-development`, **compare** là nhánh tính năng.
5. Kiểm tra các mục thay đổi, nguồn tư liệu, bản quyền và chạy kiểm thử.
6. Merge về `v3.5-development` khi đã đạt; tiếp tục kiểm thử staging.
7. Khi chuẩn bị phát hành, tạo PR từ `v3.5-development` vào `main`.
8. Chỉ Merge sau khi kiểm tra đúng gói web sẽ xuất bản; kiểm tra tab **Actions** và **Deployments** của repo.
9. Mở https://form997.github.io/Vong-co/ sau khi workflow Pages thực sự báo **success**; kiểm tra một số trang bài, bộ lọc, URL nguồn, giao diện điện thoại.
10. Nếu triển khai lỗi, mở **Actions → workflow run → job lỗi → Logs**, sửa trên nhánh phát triển rồi tạo PR mới; không sửa dữ liệu nguồn tùy tiện để cho test xanh.

**Lưu ý:** chỉ một nguồn GitHub Pages production cho mỗi repository tại một thời điểm. Muốn có trang preview độc lập theo từng nhánh, dùng GitHub Actions tạo artifact thử nghiệm, hoặc tách website staging sang repo/dịch vụ riêng; không mặc định một nhánh sẽ có một URL Pages riêng.

## 3. Chạy trang V3 trên máy để xem trước

Thực hiện từ **gốc repository** với Python 3.11+:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
python scripts/v3_build_site.py --out _site
python -m http.server 8000 --directory _site
```

Mở `http://localhost:8000/web/v3/`. Nếu `_site` đã tồn tại và script từ chối ghi đè, hãy tạo thư mục đầu ra mới (chẳng hạn `_site_preview_2`) và dùng đường dẫn tương ứng; không xóa dữ liệu tùy tiện. Có thể cần chạy thêm các validator riêng của V3.5 theo tài liệu nhánh hiện hành.

## 4. Biến môi trường — đặt đúng chỗ

**GitHub Pages tĩnh hiện tại không cần biến runtime** `HAI_LUA_HOST`, `PORT`, `DATABASE_URL`, `OPENAI_API_KEY` hoặc các biến dành riêng cho Render. Không dùng biến của dự án Hai Lúa cho dự án Vọng cổ.

Chỉ khi một workflow GitHub Actions cần token bên thứ ba hoặc tùy chọn build, mới cấu hình tại:

`Repository → Settings → Secrets and variables → Actions`

- **Variables:** dữ liệu cấu hình *không bí mật* (ví dụ `SITE_BASE_PATH=/Vong-co/`, nhưng chỉ thêm nếu script thực sự đọc tên này).
- **Secrets:** khóa bí mật, chỉ thêm khi một workflow thực sự cần. Không dán token vào README, file HTML, JS hoặc commit.
- Các quyền triển khai Pages nên dùng cơ chế quyền tối thiểu và token mặc định của workflow khi phù hợp; không tự tạo PAT nếu chưa cần.
- Biến đặt trong GitHub Settings **không tự động đi vào HTML/JavaScript**. Chỉ workflow có lệnh dùng biến mới nhận được. Tuyệt đối không xuất secrets vào tập tin công khai.

### Quy tắc đặt tên biến

1. Chữ in hoa không dấu: `VONG_CO_BUILD_MODE`.
2. Dùng dấu gạch dưới, không có khoảng trắng.
3. Trong Python hoặc workflow phải đọc **đúng cùng tên**.
4. Chỉ đặt khi có mã sử dụng; không thêm biến cho đẹp.
5. Không đổi cấu hình production trước khi thử staging.

## 5. Khi nào mới dùng Render?

Chỉ cần Render hoặc dịch vụ máy chủ tương tự **khi dự án có backend chạy thường trực** (ví dụ API, truy vấn cơ sở dữ liệu, TTS hoặc MCP server). Khi đó, cần tạo dịch vụ **riêng**, rà lại mã nguồn và lệnh chạy; biến `HOST`, `PORT` phụ thuộc backend thực tế. Website Pages tĩnh hiện tại **không tự chạy Python/MCP** cho người truy cập.

## 7. Các lỗi thường gặp

| Triệu chứng | Nơi kiểm tra |
|---|---|
| Merge thành công nhưng web chưa thay đổi | Actions, cấu hình Pages, nhánh nguồn triển khai, cache trình duyệt |
| Build lỗi | Logs, phiên bản Python, đường dẫn scripts, dữ liệu JSON, thư mục output |
| Một nhánh không có URL riêng | Pages chỉ có một site production/repository; cần cơ chế preview riêng |
| Đặt biến nhưng JS không đọc được | GitHub Actions vars khác biến trong JavaScript chạy ở trình duyệt |
| GitHub báo giới hạn | Phân biệt API rate limit, Actions quota, Pages limit, dung lượng, quyền tài khoản |
| API key lộ trong Git | Thu hồi/đổi khóa, loại khỏi mã và lịch sử phù hợp; không chỉ xóa dòng hiện tại |
