# V3.6 — Tự động dò metadata Internet, bảo vệ nhánh

**Ngày bắt đầu:** 31/10/2026. **Trạng thái:** scanner học thuật có kiểm soát; KHÔNG tự thẩm định hoặc đăng bài bản.

## Phạm vi công nghệ

- **Crossref REST API công khai**: tìm nhan đề và DOI theo từ khóa; không cần API key.
- **OpenAlex REST API**: tùy chọn khóa miễn phí do chủ kho cung cấp, đặt trong GitHub Actions Secrets với tên OPENALEX_API_KEY. Thiếu khóa sẽ bỏ qua nguồn này để tiết kiệm hạn mức.
- **Python 3.11, chỉ dùng thư viện chuẩn**: giới hạn số truy vấn, lọc nhan đề liên quan, chuẩn hóa DOI, loại trùng, chặn endpoint không cho phép, giới hạn kích thước phản hồi.
- **GitHub Actions trên main**: theo lịch vào khoảng 09:17 giờ Việt Nam, có thể trễ theo hạ tầng GitHub; cũng có thể chạy thủ công.
- **GitHub Issues và Actions artifact**: tối đa một Issue đang mở về nguồn chờ kiểm, artifact lưu 14 ngày. Token có quyền issues:write và contents:read; KHÔNG có quyền push mã nguồn hay ghi vào catalog.

**Không sao chép PDF, lời ca, ký âm, nhạc thu hay nội dung có quyền hạn chế.** Metadata từ Internet có thể không chính xác; phải đối chiếu nguồn gốc, tác giả, trang/chữ nhạc và quyền trước khi sửa website. **0/20 bài nghiệm thu diễn xướng.**

## Kiểm thử ngoại tuyến

~~~bash
python -m unittest discover -s tests -p "test_v3_6_discovery.py" -v
~~~

## Quét thử với Internet

~~~bash
python scripts/v3_6_discover.py --out v3_6_pending.json --issue-body v3_6_pending.md
~~~

Không commit tệp kết quả chưa kiểm định. Nếu toàn bộ nguồn mạng lỗi, scanner trả mã lỗi chứ không báo thành công.

## Quy trình thẩm định và công bố

Internet metadata → Issue/Artifact **chờ kiểm** → người duyệt đối chứng nội dung nguồn thực, tác quyền và dị bản → tạo Pull Request riêng → GitHub Actions Python/Chromium → Merge vào v3-development → GitHub Pages. **Robot không tự nâng status** từ pending thành approved.

## Bảo vệ nhánh quan trọng

Vào Settings → Rules → Rulesets (cần quyền quản trị):

1. Tạo protect-v1-frozen cho nhánh v1-frozen: chặn xóa, force push và cập nhật trực tiếp.
2. Tạo protect-main cho main: PR bắt buộc, kiểm tra CI đúng tên, chặn force push.
3. Tạo protect-v3-deploy cho v3-development: PR và kiểm thử Python + Chromium, cấm force push và xóa nhánh.
4. V2 làm hồ sơ nghiên cứu, không cấp robot quyền sửa v2-development.
5. Nếu repository chỉ có một người, yêu cầu một approval từ người khác sẽ chặn chính chủ phát hành; cấu hình PR, CI và review phù hợp số cộng tác viên.

**Việc tạo tệp hướng dẫn không tự bật Rulesets.** Người quản trị phải thực hiện trên GitHub hoặc cấp công cụ có quyền quản trị.
